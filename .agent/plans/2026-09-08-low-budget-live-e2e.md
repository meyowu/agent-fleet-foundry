## Proposed design

1. Public `fleet run` options build the already validated `RunBudgetLimits` and forward them to the existing workflow. Omitted flags preserve defaults; invalid input fails before creating a Run.
2. Live init uses the same deterministic bootstrap/real Docker gate. The test then creates a `live-canary` profile and binds it as the disposable project's default.
3. The real task uses the ordinary PydanticAI adapter, CLI and control plane. No monkeypatch substitutes a live role, broker, sandbox or completion decision.
4. The test verifies unchanged target source/HEAD, an exact single-file candidate patch, real completed role usage, isolated command receipts, independent verification, complete accounting and zero outstanding leases.
5. Register cleanup before init. On failure, discover exact outstanding run IDs, use cancellation/recovery only after the owner is stopped, retain artifacts and export original and cleanup outcomes separately.
6. A one-attempt launcher creates a new private evidence directory, executes only the live test in the key-owning terminal, captures bounded diagnostics, and reports the artifact location. A repeated launch against an existing attempt must not silently spend again. The launcher does not run fallback recovery: missing/incomplete finalization or forced interruption cannot prove detached trusted Docker/Git subprocesses stopped. Such outcomes retain evidence and require explicit reconciliation.
