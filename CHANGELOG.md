# Changelog

## 0.1.0 — unreleased local-first release candidate

- Repository-aware static profiling, bounded command discovery, ProjectKnowledge,
  reviewed FleetSpec and isolated disposable bootstrap canary with evidence.
- Adaptive CoS direct/single/pair/parallel/specialist strategies, ephemeral role
  instances, deterministic joins and persistent bounded project chat.
- Independent exact PermissionBroker/Gateway, user-owned trust, once/run/project
  approvals, explain/revoke/reset and durable non-replayable dispatch claims.
- Exact fake/Docker/explicit-local-unsafe selection; hardened local Docker command
  inspection, bounded execution, cancellation and exact owned-resource recovery.
- Docker shadow-file lifetime pinning and pre-dispatch metadata revalidation,
  including inode-reuse rejection and bounded descriptor cleanup.
- Immutable content-addressed evidence, independent verification and explicit
  code-patch apply; simulated/unsafe/incomplete evidence cannot verify completion.
- Bounded explicit BYOK PydanticAI adapter and cumulative budgets; no actual live
  provider acceptance or general provider-history restoration is claimed.
- Reviewed FleetPatch proposals, typed path-conditioned verification requirements,
  native whole-tree atomic publication, monotonic admission, current-head inverse
  rollback and conservative process-crash recovery. Protected authority is unchanged.
- SQLite migrations1–8; preserve historical wire bindings. Once headed, project
  reinitialization is rejected, including credential-reference-only rebinding.
  Key value rotation behind the existing reference is allowed; protected setup
  changes require a separate registration with prior state preserved.
- Packaged pinned runner v1, public learning project and detailed Chinese user
  guide, fresh wheel/sdist checks, upgrade/scale/security replay and platform CI.

Compatibility limits: Python3.12–3.14, Git>=2.45, local macOS/Linux native publication,
local Unix Linux Docker daemon, UTF-8 bounded code/configuration patches, supported
exact filesystem metadata. No arbitrary shell, worker networking, remote/hosted
provider, VM-strength hostile-host isolation or automatic package publication.

"Unreleased" is intentional. Exact acceptance/checkpoint/merge status is recorded
in the ledger; owner license authorization and an explicitly credentialed live
canary remain separate public-release prerequisites.
